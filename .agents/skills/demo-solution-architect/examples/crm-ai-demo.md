# 示例：AI分析CRM客户历史订单（示范，不是实际验证）

## 目标
允许获授权的外贸业务人员按客户查看历史询盘/订单并得到 AI 跟进建议。只读优先，不自动更改 CRM 数据。

## 候选接入路线
| 路线 | 核心技术 | 适用条件 | 主要风险 |
|---|---|---|---|
| 官方 API | HTTP/REST/JSON/鉴权 | 厂商开放所需字段及权限 | 接口范围、费用、限流 |
| 数据库只读 | SQL/ODBC/视图/ETL | 获得批准的只读账户及表结构 | 版本变更、安全与数据一致性 |
| 数据文件导出 | CSV/Excel/批处理 | 允许批量导出且不要求实时 | 更新滞后、格式变更 |
| RPA | UI 自动化/异常恢复 | 经授权的老旧系统缺少其他路径 | 操作脆弱、性能低、维护高 |

## 数据利用层
固定的订单统计由程序或 SQL 做；非结构化邮件摘要可由 LLM 处理；敏感写回需要独立审批和审计。可能的编排方案有工作流、普通后端程序、Agent工具调用或混合系统。

## 原理微课
1. ODBC：数据库访问驱动接口，不等于把数据库变成 AI 工具。
2. ETL：抽取、转换、加载数据；用于规范字段、清洗和同步。
3. Webhook：事件触发的 HTTP 回调，与轮询接口的工作节奏不同。

## 举一反三
转向 ERP 实时库存分析时，数据新鲜度改变技术选型，可进一步认识缓存、事件驱动和消息队列。仅作为学习方向，不意味着必然需要上述组件。

## 验证优先级
先确认合法授权和可访问字段，再用小规模脱敏数据验证正确性及权限；最后才做 AI 展示。所有结论目前仅为设计示例。
